ที่มาของข้อมูล (จาก description)

คำนวณจากรายการซื้อขาย USD กับ THB ระหว่างธนาคาร ที่มูลค่าตั้งแต่ 1 ล้าน USD ขึ้นไป เฉลี่ยถ่วงน้ำหนักด้วยปริมาณซื้อขาย

  • ธนาคารพาณิชย์ที่จดทะเบียนในไทย
  • สาขาธนาคารต่างประเทศ
  • สถาบันการเงินเฉพาะกิจ
เอกสารวิธีคำนวณ (PDF) ↗

Endpoint ทั้ง 4 เส้น

ทุกเส้นเป็น GET รับ start_period และ end_period บังคับทั้งคู่ ต่างกันที่รูปแบบช่วงเวลา โจทย์ใช้แค่เส้นรายวัน

Path ความถี่ รูปแบบ period ตัวอย่าง ประกาศ คำนวณจาก
/DAILY_REF_RATE/ ใช้ รายวัน YYYY-MM-DD 2017-06-30 ทุกวันทำการ 18:00 น. รายการซื้อขายระหว่างวัน
/MONTHLY_REF_RATE/ รายเดือน YYYY-MM 2017-06 วันทำการสุดท้ายของเดือน 18:00 น. เฉลี่ยจากเรตรายวัน
/QUARTERLY_REF_RATE/ รายไตรมาส YYYY-QN 2017-Q1 วันทำการสุดท้ายของไตรมาส 18:00 น. เฉลี่ยจากเรตรายเดือน
/ANNUAL_REF_RATE/ รายปี YYYY 2017 วันทำการสุดท้ายของปี 18:00 น. เฉลี่ยจากเรตรายไตรมาส

สิ่งที่ spec ไม่ได้เขียนไว้ แต่เจอตอนยิงจริง

  • !ขอได้ไม่เกิน 31 วันต่อครั้ง ข้อค้นพบ
  • !วันที่ไม่มีข้อมูลได้ [{"period":"","rate":""}] ข้อค้นพบ
  • !error 400, 401, 403, 404 และรูปแบบ body ของแต่ละแบบ ข้อค้นพบ
  • !header X-RateLimit-* มีค่าแต่ใช้ไม่ได้ ข้อค้นพบ

คำผิดในต้นฉบับ: "Intebank" ใน description ของเส้นรายวัน, "End Preiod Date" ในเส้นรายวัน รายไตรมาส และรายปี และ components.parameters ใช้รูปแบบ YYYY-QN ของรายไตรมาสเป็นค่ากลาง (ไม่มี endpoint ไหนอ้างถึง)

อ่านตารางนี้ยังไง

เรตอ้างอิงอยู่ระหว่างราคารับซื้อกับราคาขายของธนาคารทุกวัน และใกล้กับ mid_rate แต่ไม่เท่ากัน ต่างกันได้ถึง 0.03 บาท บางวันสูงกว่า บางวันต่ำกว่า

ส่วนต่างรับซื้อกับขาย (selling − buying_transfer) ราว 0.33 บาท คือส่วนต่างที่ลูกค้าจ่ายให้ธนาคาร ซึ่งไม่มีในเรตระหว่างธนาคาร

สรุป: ถ้าหยิบ mid_rate มาแทน เลขจะดูใกล้จนไม่มีใครสังเกต แต่ผิดทุกแถว นี่คือเหตุผลที่ต้องดู path Stat-ReferenceRate ให้แน่ใจ

จุดผิดในข้อมูลจริงของ ExchangeRate: ชื่อสกุล GBP สะกด "POUND STERING" และ currency_name_eng บางสกุลมีช่องว่างต่อท้าย เช่น "USA : DOLLAR (USD) " ถ้าจะใช้ชื่อเป็น key ต้อง trim ก่อน หรือใช้ currency_id แทน
